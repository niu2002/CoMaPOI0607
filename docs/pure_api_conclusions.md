# 协同多 Agent POI 预测：纯 API 方案对照实验与结论汇总

本文件记录并汇总了基于阿里云百炼 API 兼容接口（`qwen-plus` 决策模型、`text-embedding-v3` 检索模型、`qwen3-rerank` 重排模型）在前向推理模式下进行的多次对照评测结论，重点定量探究了云端 RAG 检索对协同多 Agent 系统性能的最终指标贡献率。

---

## 1. 101 样本对照实验设计与配置

对照实验共评估了以下两个不同配置的评测方案，所采用的测试样本完全对齐（CA 数据集 101 个测试样本，并发度 batch_size=4）：

* **配置方案 A（云端 RAG 增强版）**：
  * **向量提取 & 检索**：调用百炼云端 `text-embedding-v3` 批量编码 13,628 个 POI，建立 NumPy 邻近索引；测试时 query 先通过向量检索召回 Top-100。
  * **重排二次过滤**：调用云端 `qwen3-rerank` 重排这 100 个候选，提取 high-score 的前 50 个输入到融合候选池（`fused_candidate_top_k=50`）。
  * **Agent 推理决策**：三 Agent（Profiler、Forecaster、Predictor）均采用云端 `qwen-plus` 大模型。
* **配置方案 B（纯 Agent 推理版 - 无 RAG 候选）**：
  * **向量提取 & 检索**：完全剔除 RAG 检索候选，不提供任何向量检索结果。
  * **融合候选池**：仅依靠用户最近/频繁签到历史、物理地理邻近、品类相似度与全局热门的 RRF 融合。
  * **Agent 推理决策**：三 Agent（Profiler、Forecaster、Predictor）均采用云端 `qwen-plus` 大模型。

## 3. 核心学术结论与机制分析

基于上述量化指标，可以得出以下核心学术结论：

### 3.1 “信息稀释与黄金候选挤占假说” (Information Dilution & Candidate Crowding Out)
在 Top-5 与 Top-10 召回中，方案 B 的 HR@10 达到了 **39.60%**，高出方案 A（36.63%）近 **3 个百分点**。这种“引入云端重排 RAG 检索却导致召回率下降”的反常现象，可以通过以下理论机制来解释：
1. **地缘物理连续性与历史高粘性（主导预测特征）**：
   下一步 POI 预测高度依赖用户的历史行为规律（时间与频率）及空间临近程度。在 RRF 融合排序中，`history_recent`（权重 1.2）与 `history_freq`（权重 1.0）是精度极高的“黄金信号”。
2. **多余 RAG 候选带来的空间噪声**：
   方案 A 引入的 `rag_top100` 候选包含了多达 100 个在向量空间相近但用户可能从未访问过的 POI。因为基数很大且享有较高的融合权重（1.0），它在进行 RRF (Reciprocal Rank Fusion) 时产生了强烈的“挤占效应”。
3. **高可信度候选的溢出**：
   由于最终输入给 Agent 3 的候选列表长度被强制截断为 50（`fused_candidate_top_k=50`），许多原本包含在 `history_recent` / `history_freq` 里的后排真实黄金目的地被大量混入的 RAG 负样本挤出了 Top-50，最终导致 Agent 3 决策时只能从充满噪音的候选池里选择，降低了 Top-5 / Top-10 召回率的上限。

### 3.2 局部区间 Rerank 精度优势
相比之下，在 Top-3 重排区间，方案 A（NDCG@3 达 **18.84%**，HR@3 达 **21.78%**）微弱领先方案 B。这表明，在极少数特定场景中，云端重排模型（`qwen3-rerank`）对于 Top-3 的超高可信候选有正向纠偏作用。但在更宽的截断区间中，RRF 挤占效应的负面拖累成了主导指标变化的决定性因素。

## 4. 后续研究与参数调整指南

1. **RAG 截断宽度收窄**：将 RAG 召回的候选数量由 Top-100 缩减至 Top-15 ~ Top-20。这能将绝大多数无地缘粘性的向量噪声过滤掉，极大保全融合候选池的纯度。
2. **调整 RRF 权值权重**：在 `candidate_fusion.py` 中将 `rag_top100` 的 RRF 权重由当前的 `1.0` 降为 `0.5` ~ `0.6`，使得系统能够优先保全 `history_recent` 和 `history_freq` 的位置。
3. **基于预置向量的高速离线验证**：借助预生成的 `.npy` 特征库在远程 AMD 服务器上实现零 Token 的 FAISS 自适应加载，极大提高了参数搜索和对比验证效率。
